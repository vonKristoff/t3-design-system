# Design System Builder

Visually configure a semantic colour and typography system, preview it against a real
Markdown document, then generate a single `bunx` command that reproduces exactly the same
theme locally.

**Live app:** https://design-system-builder.jeancnicolas.workers.dev

The whole product rests on one guarantee: *what you see in the web preview is exactly what
the CLI generates.* There is no second colour engine to drift out of sync.

---

## Why

Theme configuration tools usually fail in one of two ways. Either they hand you raw
`oklch(0.623 0.214 259.815)` values and expect you to know what you're doing, or they give
you a pretty picker whose output the export command quietly approximates.

This one gives you human inputs (`blue-600`) and guarantees byte-identical output, because
the browser and the CLI both call the same `@tsup-system/core` functions.

```
             ┌──────────────────────┐
             │  @tsup-system/core   │
             │  • OKLCH scale gen   │
             │  • payload codec     │
             │  • CSS generator     │
             └──────────┬───────────┘
             ┌──────────┴───────────┐
        packages/web            packages/cli
```

## Quick start

```bash
bun install

bun run web:dev      # start the builder at localhost:5173
bun test             # run core + CLI tests
```

Deploy the web app to Cloudflare Workers:

```bash
bun run web:deploy   # builds, then wrangler deploy
```

The app is fully prerendered, so it ships as static assets with no Worker runtime and
essentially zero cost.

## The workflow

1. **Open** the builder. You land on a populated, attractive Markdown preview — nothing to configure first.
2. **Pick colours.** Each semantic anchor is a Tailwind palette entry (`blue-600`, `fuchsia-500`), chosen from a visual swatch grid. No raw RGB, HSL or OKLCH entry anywhere.
3. **Pick fonts.** Assign Google Fonts to the `primary`, `secondary` and `tertiary` roles, and route Markdown elements to those roles.
4. **Watch the preview update.** Every change is instant. No save button, no debounce round-trip.
5. **Copy the command.**

```bash
bunx @threejjjs/dsb --theme="eyJ2ZXJzaW9uIjoxLCJjb2xvcnMiOns..."
```

6. **Run it** in any project directory. The CLI decodes the payload and writes a theme directory.

## The colour model

No generic `primary` / `secondary` pair. Eleven semantic anchors, grouped so the UI can
present them as cards:

| Group | Anchors | Role |
| --- | --- | --- |
| **Surfaces** | `base` `alt` `glass` | Page background, cards and code blocks, frosted panels |
| **Content** | `prose` `muted` `inverse` | Body copy, secondary text, text on contrasting fills |
| **Emphasis** | `accent` `pop` | Links and controls, sparing highlight colour |
| **Traffic** | `stop` `warning` `ok` | Errors, cautions, confirmations |

Plus fixed chromatics `black` and `white`, which still get full generated ranges.

Each anchor becomes a complete 11-step scale — `50` through `950` — generated by
interpolating **OKLCH**, not HSL. Perceptual interpolation is what keeps a hue's
character intact as it lightens and darkens, instead of the muddy or neon artefacts HSL
shading produces.

```
--accent-50 … --accent-950     from anchor "blue-600"
--pop-50 … --pop-950           from anchor "fuchsia-500"
```

Anchors also emit a constrained relative trio (`--{semantic}`, `--{semantic}-light`,
`--{semantic}-dark`) for surfaces that need to shade in either direction. When an anchor
sits too close to white for a step to fit, the extreme slot rotates 90° rather than
collapsing onto the anchor — so the trio always spans light to dark with every slot
distinct.

Contrast is surfaced as **warnings**, never as silent corrections. If `prose` on `base` is
going to be hard to read, you'll be told; your choice stays your choice.

## Typography

Three optional font roles — `primary`, `secondary`, `tertiary` — each with a variable-font
weight axis where the family supports one. Elements (`h1`…`h6`, `p`, `list`, `blockquote`,
`code`) route to roles, and anything left unassigned falls back sensibly.

Markdown typography follows [Splendor](https://github.com/markdowncss/splendor)'s
font-stack approach as the baseline; your chosen fonts override it. `tertiary` is emitted
only when set — an unconfigured role never produces an invalid declaration.

## The payload

`ThemeOptions` is the single canonical theme representation. The web app serialises it,
the CLI deserialises it, and both hand the identical object to the same engine.

```
ThemeOptions → JSON.stringify → deflate (pako) → base64url → one CLI argument
```

and exactly reversed on the way back. Base64url keeps it shell-friendly and free of
characters that need escaping. Payloads are versioned; the CLI rejects versions it doesn't
recognise with a plain-language error rather than a stack trace.

## Generated output

```bash
bunx @threejjjs/dsb --theme="..." --out theme
```

```bash
theme/
├── root.css        # semantic colour scales + font/weight variables
├── fonts.css       # Google Fonts imports and stacks
├── base.css        # html, body, a, hr, img, .glass-panel
├── typography.css  # headings, body copy, strong, em
├── markdown.css    # blockquote, lists, tables, pre, code
├── layout.css      # content measure, breakouts, grid routing
├── tw-bridge.css   # Tailwind v4 @theme bridge (optional)
└── index.css       # imports the above
```

Every colour reference is a semantic variable. No hardcoded Tailwind palette values leak
into the output, and no component depends on `blue-600` directly.

### Tailwind

`tw-bridge.css` wires the generated variables into Tailwind v4's `@theme`, so utilities
consume the theme instead of bypassing it:

```html
<div class="bg-base-50 text-prose-800 font-primary">Ships with your system</div>
```

The bridge is a plain CSS file — edit it afterwards to customise the mapping.

## Layout

```bash
packages/
├── core/     # OKLCH engine, payload codec, CSS generator  (the source of truth)
├── web/      # SvelteKit builder, mdsvex preview, Tailwind v4
└── cli/      # bunx entry point — decode, generate, write
```

`core` exports the engine as source, so the browser and the CLI cannot disagree about a
value even across a version bump.
